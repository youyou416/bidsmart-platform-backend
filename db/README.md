# OceanBase 框架数据库资料

本目录仅包含 11 张 `sys_*` 基础框架表；不包含采购、供应商、竞价、报价、审批或评分表。应用启动不自动执行 DDL。本资料不创建/删除数据库，不创建租户，不更改 root 密码，也不访问旧正式系统。

## 接入前核实

用户给定本机开发参数为 `127.0.0.1:2881`、`root@sys`、`hr_score_dev`，密码由运行者安全注入。`127.0.0.1` 指后端所在机器，云端并不自动指向开发者电脑。未提供密码或实际 OceanBase 实例时，只能进行离线检查，不能宣称数据库通过验证。

请通过 OceanBase 管理端或数据库管理员核实实际产品版本/发行形态、租户名称及 MySQL 兼容模式、目标库所属租户、字符集和账号权限。端口和用户名都不足以证明这些条件。`root@sys` 是系统租户账户；生产和共享业务测试须改用业务租户及最小权限应用账户。建表/迁移账户与运行账户分离：运行账户仅获目标框架表的必要读写权限；迁移账户临时拥有建表权限。

## 版本与执行顺序

1. 注入 `DB_HOST`、`DB_PORT`、`DB_NAME`、`DB_USERNAME`、`DB_PASSWORD`；目标必须为已存在的 `hr_score_dev`。安装 MySQL 8 客户端。
2. 执行 `python3 db/tools/manage.py check`，只读取产品/库、结构和合成配置。未初始化时返回状态 2；连接/权限/结构冲突返回 1。客户端参数不含密码，临时配置权限为 0600，用完删除。
3. 独立确认租户和 MySQL 模式后执行 `python3 db/tools/manage.py init --confirm-target hr_score_dev --confirmed-mysql-tenant sys`。业务租户接入时使用已确认的租户名和相应账号；脚本仍只接受目标 `hr_score_dev`。
4. 工具先读取目标身份，再检查所有框架表。完全不存在时执行 `V001__framework_schema.sql`；完全存在且列、主键、索引、字符集相符时保留现状。部分存在或结构不符时停止。
5. 再检查合成配置。仅在全部框架表无数据时插入 `V001__synthetic_seed.sql`；已存在相同合成配置时跳过。标识冲突、不完整配置或其他既有数据需要人工核对，工具不覆盖账户密码、不修正已有授权。
6. 最后按照后端 README 显式开启一次性账户初始化。SQL 不创建账户。完成账户创建后关闭开关并移除初始秘密。

初始化需要运维隔离窗口，避免两个操作者并发执行。DDL 不假设具备事务回滚；若执行中断，工具下次会识别部分结构并停止。不要添加 `--force` 或盲目手工重跑绕过检查。先记录已执行对象，备份框架数据，在目标库内按审查后的恢复方案补齐；不通过删除重建其他数据解决问题。

脚本只要求基础 MySQL 兼容类型、普通索引、唯一键和事务，不依赖未经验证的树递归 SQL、JSON 列、CHECK 或外键能力。关联有效性、非法父节点和角色/部门循环由框架计算器验证。实际 OceanBase 支持仍需接入测试确认。

## 模型约定

| 表 | 用途 |
| --- | --- |
| `sys_user` | 账户、部门、身份/企业上下文、数据范围、版本化密码派生串、首次改密与密码版本 |
| `sys_dept` | 部门树；包含合法父节点和状态 |
| `sys_role` | 角色树及自身状态；父角色授权动态合并 |
| `sys_resource` | 目录/菜单/按钮元数据、可见/启用状态与明确权限码 |
| `sys_user_role` | 人员多角色直接关联 |
| `sys_role_resource` | 角色自有资源授权；不持久化复制继承授权 |
| `sys_user_scope_dept` | 人员指定部门范围 |
| `sys_user_purchase_type` | 未来业务采购类型代码配置；不生成业务管理模块 |
| `sys_user_material_scope` | 未来业务分管物资代码配置；空集合拒绝办理 |
| `sys_login_log` | 认证结果、来源、traceId、UTC 事件时间 |
| `sys_operation_log` | 退出、改密、授权拒绝、初始化、会话撤销等框架事件 |

ID 使用无符号 BIGINT，但 Java 层当前只生成正的 signed-long 范围值；接口 ID 以 JSON 字符串返回。不要人工写入超出 `Long.MAX_VALUE` 的标识。时间为 `DATETIME(3)`，连接会话与应用计算统一 UTC。字符集 `utf8mb4`、排序规则 `utf8mb4_bin`；用户名大小写敏感。状态为 `ENABLED`/`DISABLED`，身份预留 `BUYER`/`SUPPLIER`，资源类型 `DIRECTORY`/`MENU`/`BUTTON`。四种范围为 `SELF_AND_SPECIFIED`、`DEPARTMENT`、`ALL_DEPARTMENTS`、`DEPARTMENT_AND_SPECIFIED`。

合成配置仅有部门 `1001`（合成根部门）、独立角色 `1001`/`1002`（平台管理员/相关部门）、菜单 `1001`（FrameworkHome、`/home`、白名单组件 `Home`、`framework:home:view`），并对角色 `1001` 显式授予该资源。角色名称不推导继承、通配权限或范围放行。

## 连接与证书

初始化工具默认 `DB_SSL_MODE=VERIFY_IDENTITY`，可用 `DB_SSL_CA` 指定可信 CA。应用 prod 固定身份验证。`DB_SSL_MODE=DISABLED` 仅供明确选择的不启用数据库 TLS 的隔离回环 dev；不是连接或证书错误的修复方案。远程/生产不得关闭证书验证、启用任意公钥获取或多语句选项。数据库标准 TLS 与国密 TLS 分别核验。

## 只读检查及真实接入清单

`verification/V001__readonly_checks.sql` 可在已确认目标库内由 MySQL 客户端只读执行；不查询密码摘要、密钥、Cookie 或完整人员资料。管理视图因 OceanBase 版本与权限不同，租户/兼容模式仍需管理端确认。以下项目当前均为**待真实 OceanBase 接入验证**：

- [ ] 产品版本、MySQL 租户、`hr_score_dev` 归属、字符集、应用/迁移账户权限。
- [ ] 11 表 DDL、所有主键/唯一键/普通索引，版本脚本首次和重复执行；冲突配置保持原样。
- [ ] 中文/Unicode 配置、大小写敏感用户名、超过 JS 安全整数的长 ID 字符串往返。
- [ ] UTC 持久化/接口时区与前端 Asia/Shanghai 展示；数据库会话 `+00:00`。
- [ ] 在合成测试账户及专用测试窗口内验证事务回滚；使用全新无冲突合成标识插入目标框架表，读取后 ROLLBACK，再确认记录不存在。不得改动已有人员或授权。
- [ ] 连接失败、5 秒连接超时、10 秒查询/socket 超时、Hikari 最大连接数及权限不足时的脱敏错误。
- [ ] 账户初始化不覆盖旧账户，首次改密、会话轮换/撤销、审计写入及 30 天清理策略。
- [ ] 对启用 TLS 的连接验证可信链、主机身份和失败闭锁；如要求国密传输则另验协议、证书和网关。

H2、测试替身或单元测试通过不计入上述真实数据库核验。test启动必须显式配置独立主机、数据库、非root业务租户账号和密码，并验证TLS身份；拒绝开发库hr_score_dev和系统租户。没有测试数据库时只执行离线测试。本目录工具限定hr_score_dev并拒绝test配置，独立测试库资料需管理员单独审查后适配，不会自动修改目标。

## 升级与恢复

当前交付版本只有 V001，不运行未定义的后续迁移。未来每次升级应增加独立版本 SQL、前置结构检查、变更说明、目标库确认与恢复步骤，先在合成测试库验证；不得修改既有 V001 来覆盖现场授权。执行升级前备份受控框架数据并记录版本及对象状态，备份和日志都不得提交仓库。恢复从受控备份或经过审查的补偿步骤执行，不默认 DROP/重建，不回写账户旧密码，不越过目标库。
